Reuse Gate: pilot and continuation plan

Team ZtotheZ · Since AI Hackathon 2026, Bayer challenge "Build Less, Build Better" · 8 November 2026

Proposal. An 8-week pilot with one analytics team in one Bayer division, on real BI metadata, to measure whether Reuse Gate avoids new builds without slowing requesters down. A go or no-go decision at week 8 on thresholds agreed before the start.

1. Where we are

The prototype runs on Red Hat OpenShift AI with Bayer's synthetic Builder Data Pack: 360 reports, 56 KPI definitions, 75 semantic models, 150 business requests. On that data, 57 of 150 requests avoid a new build and all 1,098 cited rows exist. These are modelled results on synthetic data. The pilot replaces them with measured ones.

Built and tested: the decision pipeline with cited evidence and seven release gates, the clarification loop, human approval with owner and review date, least privilege for seven roles enforced by the API, the analyst dashboard studio, measured configuration changes, the executive report, the operator wall, email through n8n, a KServe decision service and a gated Tekton pipeline.

A 20-row human gold set is already prepared in the repository; the pilot team labels real requests the same way, so the recommendation quality is measured, not only the rule compliance.

5. Roles

  • Business requesters file requests and answer questions.
  • Analysts check evidence and build previews in the dashboard studio.
  • Approver (the team's BI lead) decides, with owner and review date.
  • Developers build from approved specs and propose rule changes, measured before review.
  • Governance and IT own access, the decision log and the platform.

6. Platform, security and governance

  • Runs in the division's Red Hat OpenShift AI project: the KServe decision service, the API and the UI, with the existing Tekton gates (tests, governance, evaluation, security) before every rollout.
  • Single sign-on replaces access codes; roles come from directory groups. Least privilege stays enforced by the API.
  • Language models only read requests and word text. In the pilot they run on an approved endpoint (or in-cluster on a GPU node); with no model, decisions are unchanged.
  • Read-only metadata access. No business data values leave the source systems.
  • Before scale-up: approval rights by domain, separation of duties on requests, and a tamper-evident central decision log.

8. After a go decision

Extend to the division's other analytics teams in quarter one, with .pbip export from the dashboard studio and a link from the BI request portal. Each new division plugs in through its own catalogue file (KPI vocabulary, products, markets), with no change to the decision logic.
